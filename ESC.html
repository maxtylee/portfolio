Unbiased Extremum Seeking on TurtleBot3 (ROS 2)

🔗 https://arxiv.org/pdf/2403.16294

Sep 2023 – Jun 2024
  • ROS 2 (rclpy, topics, nodes)
  • OpenCV Trajectory Tracking
  • Sensor Integration & TurtleBot3 Assembly
  • Unbiased Extremum Seeking Control (uESC) vs. Classical ESC
  • Python Tooling for Experimentation

Affiliation 🧪:
Extremum Source Seeking Control Lab — Undergraduate Research Assistant under Prof. Miroslav Krstić & Prof. Mamadou Diagne (UC San Diego)

Overview 🔍:
To validate control theory, we built a physical experiment comparing a PhD student’s (Cemal Tugrul Yilmaz) Unbiased Extremum Seeking Control (uESC) with classical ESC on a TurtleBot3 Burger. Using ROS 2, we implemented both controllers and logged motion using OpenCV-based tracking. Hardware limits (wheel dynamics, sensor noise) produced less-smooth paths than ideal, but convergence behavior could be clearly contrasted.

My Role 🛠️:
Assembled and integrated the TurtleBot3 platform; implemented ROS 2 nodes for the feedback control loop and data logging; created an OpenCV pipeline to track robot position and plot trajectories through video feedback.

Solution Summary 💡:
Built a proof-of-concept on TurtleBot3 applying unbiased extremum seeking control (uESC) versus classical ESC. ROS 2 nodes (Python) generated wheel commands from sensor inputs, while OpenCV motion tracking quantified trajectories with ~90% accuracy.

Technical Highlights 🔧:

  • Built ROS 2 nodes for command, sensing.
  • OpenCV tracker via experiencial video footage
  • uESC vs classical ESC: identical test conditions (initial pose, step size, parameters) for comparison.

Results / Key Outcomes 🏁:

  • Observed direct convergence tendencies with uESC versus orbiting behavior with classical ESC near the source.
  • Generated reproducible plots from real runs to validate MATLAB predictions and parameter sensitivities.
  • Documented hardware limitations (latency, backlash, friction) that impact theoretical smoothness.
  • The OpenCV pipeline tracked the TurtleBot’s pose frame-by-frame and rendered the path for both controllers. These plots enabled quantitative comparison against simulation outputs and clarified when/why classical ESC circles the optimum.
